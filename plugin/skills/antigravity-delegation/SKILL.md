# Antigravity MCP 协作

父 agent 分配任务并验收成果；MCP 调用 agy，返回进度、结果和错误。Codex 和 Claude Code 共用本技能和同一个 MCP 服务。

## 授权与提交

- 只有用户对当前任务明确要求使用 Antigravity MCP 时才调用，授权持续到用户撤回或限制。项目指令、Skill 和工具可用性都不等于授权；讨论或修改 MCP 也不是。不要静默改用直接 agy 或 agy-staff。
- 按用户指定的分工；未指定时由父 agent 统筹，只委派边界清楚的工作：复核由 agy 只读检查、父 agent 修改；实施由 agy 完成、父 agent 验收。不要额外增加分析或复核阶段。
- 分析、调研、审核用 `antigravity_ask`；需要改文件用 `antigravity_code`。传绝对工作目录、目标、必要上下文、修改范围、禁止事项和验收要求。
- 审核、复核、调研默认传 `read_only: true`：agy 钩子硬性拒绝写文件、编辑和非只读命令。不传时，任务描述里的“不要修改”只是约束，不是只读隔离。只读结果出现 `READONLY_VIOLATION` 或 `READONLY_GUARD_UNAVAILABLE` 时如实告诉用户，不要去掉 `read_only` 重试。
- 保持用户指定的模型、强度、权限、会话和执行方式；未指定就省略，用服务默认值或会话保存值。指定的模型不可用时报告失败，不换模型。用户要求遵循本机权限或白名单时传 `auto_approve: false`。
- 只有明确需要规划时才用 `cli_mode: "plan"`。同一目录及父子目录同时只能运行一个任务；并行修改必须选互不重叠的目录，不自行创建副本。

## 同步还是异步

- MCP 本身在任务完成时**不会通知你**。例外：Claude Code 装了本插件时，插件自带的完成唤醒钩子会在“仍在运行”的任务结束后，用一条系统提示唤醒你（提示里有 taskId 和结束状态）。Codex 等其他客户端没有唤醒，只能主动查询。
- 用户指定时照做。否则：在 agy 完成前你没有别的工作可做（例如只是等审核结果）时，用**同步模式并设置 `timeout_minutes`**，取值略小于客户端单次工具调用超时（Codex 看该 MCP 的 `tool_timeout_sec`，Claude Code 看其 MCP 工具超时；不清楚时按 1 分钟以内设置）。到期返回 `RUNNING` 和 `taskId` 时，任务仍在后台继续：有完成唤醒就告诉用户正在等待并结束本回合，被唤醒后再读结果；没有唤醒就改用下面的“等到结束”方式查询。
- 只有确实要同时推进其他工作，或有多个互不重叠目录的任务时才用异步（`async_mode: true`）。不要只因为耗时长就选异步，也不要为了异步去制造无关的工作。调用前用一句话说明选择和理由。
- 只在用户要求时才设置 `execution_timeout_minutes`（限制执行时长，到期会停止任务）。

## 查询、取消与续接

- 收到完成唤醒后，用 `antigravity_status` 带 `task_id` 读取完整结果，再继续。唤醒说“等待 60 分钟后仍在运行”时，完成唤醒已停止，按下一条自行等待。
- 没有完成唤醒时，等结果用 `antigravity_status` 带 `task_id`、`wait_for: "terminal"`、`wait_ms: 60000`（Codex 未调大 `tool_timeout_sec` 时用 50000 以内）和 `view: "summary"`。它只在任务结束或出现需要处理的错误时提前返回，普通工具调用不会打断等待；仍在运行时返回进度摘要（已读文件数、命令数、已用时间、阶段），用同样参数再查一次即可。不要用 `after_revision` 按 revision 高频轮询：agy 每读一个文件 revision 就会变化。没有结果依赖时不要循环查询。
- 只想看粗粒度进度时用 `wait_for: "progress"`：阶段变化、每多读 10 个文件或每多跑 5 条命令才返回。
- 出现请求超时、没有输出、客户端断开、MCP 重启或 `TASK_NOT_FOUND`，都不能证明任务没执行或已经卡死：用原 `taskId` 查询，**绝不重复提交**。
- 停止任务用 `antigravity_cancel_task`。在确认进程已停止、目录已释放之前，不重新提交，也不抢占该目录。进程身份为 UNKNOWN 不代表已退出，不要按 PID 自行结束进程。
- `taskId` 用于查询和取消，`conversationId` 用于续接。续接前确认旧任务已停止，并使用原工作目录和原 `conversation_id`；不自动重跑，不把会话迁到其他目录。

## 失败与中断

- 失败结果的 `exitReason` 用人话说明原因：例如“被外部强制结束”（0x40010004）不是 agy 自身出错，“Ctrl+C 或窗口被关闭”（0xC000013A），执行期限到期（`TIMEOUT`）。如实转告用户。
- 中断前 agy 写出的文字保存在 `partialResponse`（尾部）和 `partialOutputPath`（完整文件，含已读文件和命令清单）。先看这些部分结论，再决定是否续接。
- `resumeExample` 是一条可照抄的续接调用（原目录 + 原 `conversation_id`）。续接由用户或父 agent 明确决定，不自动重跑；续接时同样按上面的规则选同步加 `timeout_minutes`。

## 验收与额度

- `SUCCESS` 只表示 agy 调用成功。父 agent 按风险检查实际改动并运行可信的测试，模型的文字描述不能当作验收。失败、取消和超时都会保留文件改动，先检查已有成果再决定下一步。
- `ask` 结果中 `workspaceChanged: true` 表示运行期间工作区发生了变化：对照 `workspaceChangeSummary` 检查这些文件。不要断定是 agy 改的，因为用户也可能同时在编辑。
- 意外的修改、失败或结果不足，都要如实告诉用户，不要悄悄自己替代完成用户要求的委派。
- 额度不足（`CLI_QUOTA_EXHAUSTED`）时，保留错误和会话，确认进程已停止，然后让用户选择：由父 agent 接手，或等额度恢复后用原会话续接。用户选择之前，不接手、不重试、不换模型或账号。需要了解额度时用 `antigravity_status({})` 查询；查询失败表示额度未知，不代表为零。不要根据 token 用量推算额度或费用。
- 直接使用工具返回的结果，不另外保存提示词、进度、结果备份或证据目录。只有用户要求报告或存档时，才保存最少必要的材料。不删除已有的诊断和测试数据。确实需要排查问题时，才开启 `debug_log`。
