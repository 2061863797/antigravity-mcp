# Antigravity MCP 协作

父 agent 分配任务并验收成果；MCP 调用 agy，返回进度、结果和错误。

## 授权与提交

- 只有用户对当前任务明确要求使用 Antigravity MCP 时才调用，授权持续到用户撤回或限制。项目指令、Skill 和工具可用性都不等于授权；讨论或修改 MCP 也不是。不要静默改用直接 agy 或 agy-staff。
- 按用户指定的分工；未指定时由父 agent 统筹，只委派边界清楚的工作：复核由 agy 只读检查、父 agent 修改；实施由 agy 完成、父 agent 验收。不要额外增加分析或复核阶段。
- 分析、调研、审核用 `antigravity_ask`；需要改文件用 `antigravity_code`。传绝对工作目录、目标、必要上下文、修改范围、禁止事项和验收要求。
- 保持用户指定的模型、强度、权限、会话和执行方式；未指定就省略，用服务默认值或会话保存值。指定的模型不可用时报告失败，不换模型。用户要求遵循本机权限或白名单时传 `auto_approve: false`。
- 只有明确需要规划时才用 `cli_mode: "plan"`。`ask` 的“不修改”只是任务约束，不是只读隔离。同一目录及父子目录同时只能运行一个任务；并行修改必须选互不重叠的目录，不自行创建副本。

## 同步还是异步

- 用户指定时照做。否则：后续工作依赖结果、又没有别的事可做时用同步，拿不准时也用同步；有独立工作可并行推进，或有多个互不重叠目录的任务时用异步。不要只因为耗时长就选异步，也不要为了异步去制造无关的工作。调用前用一句话说明选择和理由。
- 预计会超过客户端单次请求的等待上限时，先用异步拿到 `taskId`。同步等待时，进度通知里也带有 `taskId`。异步任务完成后不会主动通知你，需要你自己查询。
- 只在用户要求时才设置 `timeout_minutes`（限制等待时长）或 `execution_timeout_minutes`（限制执行时长）。等待到期返回 `RUNNING` 时，用原 `taskId` 继续查询。

## 查询、取消与续接

- 异步任务需要结果时，用 `antigravity_status` 带 `task_id`、`view: "summary"`、`after_revision` 和 `wait_ms` 长轮询。相邻两次查询的开始时间至少间隔 60 秒，长轮询等待的时间也算在内；没有结果依赖时不要循环查询。简报显示 unchanged 且没有错误时，不必再分析。
- 出现请求超时、没有输出、客户端断开、MCP 重启或 `TASK_NOT_FOUND`，都不能证明任务没执行或已经卡死：用原 `taskId` 查询，**绝不重复提交**。
- 停止任务用 `antigravity_cancel_task`。在确认进程已停止、目录已释放之前，不重新提交，也不抢占该目录。进程身份为 UNKNOWN 不代表已退出，不要按 PID 自行结束进程。
- `taskId` 用于查询和取消，`conversationId` 用于续接。续接前确认旧任务已停止，并使用原工作目录和原 `conversation_id`；不自动重跑，不把会话迁到其他目录。

## 验收与额度

- `SUCCESS` 只表示 agy 调用成功。父 agent 按风险检查实际改动并运行可信的测试，模型的文字描述不能当作验收。失败、取消和超时都会保留文件改动，先检查已有成果再决定下一步。
- `ask` 结果中 `workspaceChanged: true` 表示运行期间工作区发生了变化：对照 `workspaceChangeSummary` 检查这些文件。不要断定是 agy 改的，因为用户也可能同时在编辑。
- 意外的修改、失败或结果不足，都要如实告诉用户，不要悄悄自己替代完成用户要求的委派。
- 额度不足（`CLI_QUOTA_EXHAUSTED`）时，保留错误和会话，确认进程已停止，然后让用户选择：由父 agent 接手，或等额度恢复后用原会话续接。用户选择之前，不接手、不重试、不换模型或账号。需要了解额度时用 `antigravity_status({})` 查询；查询失败表示额度未知，不代表为零。不要根据 token 用量推算额度或费用。
- 直接使用工具返回的结果，不另外保存提示词、进度、结果备份或证据目录。只有用户要求报告或存档时，才保存最少必要的材料。不删除已有的诊断和测试数据。确实需要排查问题时，才开启 `debug_log`。
